### Findings

- [x] **R1 — MEDIUM — naming** — `src/Concertable.Shared/src/Seed/Concertable.Seed.Shared/Identity/SeedingScope.cs:1`
  Deleting `SeedingIdentityRewriter` and `SeedingIdentityInterceptor` left `SeedingScope` as the sole
  occupant of a folder and a public namespace called `Identity`, and `SeedingScope` is not identity
  machinery — it is the "seeding is in progress" depth flag that `SeedingDomainEventDispatchInterceptor`
  and `IntegrationDbInitializer` read here, and that B2B's and Customer's `DevDbInitializer` read
  downstream. The namespace now names code that no longer exists, which is the misleading surviving shape
  the pre-launch rule says to delete rather than preserve. Fix: move `SeedingScope` to the package root as
  `Concertable.Seed.Shared`, drop the `Identity` folder, and move the five `using` sites with it. This
  costs the consumer sweep nothing extra — removing `UseSeedingSupport` already makes this train a
  publish-then-bump break, and `DevDbInitializer` is a file that sweep already has to touch.

  Resolved in the remediation commit: `SeedingScope.cs` moved to the package root under
  `Concertable.Seed.Shared`, the `Identity` folder is gone, and the three platform `using` sites moved
  with it - `SeedingDomainEventDispatchInterceptor` and `IntegrationDbInitializer` already imported
  `Concertable.Seed.Shared`, so both shed an import rather than gaining one, and
  `SeedingServiceCollectionExtensions` dropped its `Identity` import outright. Non-incremental Release
  build 0 errors and the same single pre-existing `CS8603` recorded below; `Seed.Shared` 11/11,
  `Testing.Integration` unit 20/20 and integration 10/10, `DataAccess` integration 31/31.

### Verified, not findings

- **The identity rewrite is provably unreachable, not merely unused.** `RequiresIdentityInsert` answered
  `false` for `Npgsql.EntityFrameworkCore.PostgreSQL`, so `SeedingIdentityInterceptor.Rewrite` returned
  before touching the rewriter; both regexes, `BuildTableMap` and the multi-table guard were dead the
  moment the last service left SQL Server.
- **No guard died with it.** `RequiresIdentityInsert`'s `NotSupportedException` for an unrecognised
  provider only protected the rewrite it gated, and the InMemory provider the seed unit tests use issues
  no `DbCommand`, so it never reached that switch.
- **PostgreSQL needs no equivalent.** Npgsql maps an EF `ValueGeneratedOnAdd` key to
  `GENERATED BY DEFAULT AS IDENTITY`, which accepts an explicit value with no `OVERRIDING SYSTEM VALUE`,
  and the sequence divergence that follows is owned by the reset path — `PostgresFixture` builds its
  `Respawner` with `WithReseed = true`.
- **`AddSqlServerContainer` has no caller anywhere.** Re-verified against fetched `origin/main` on all
  thirteen repositories: the only surviving mentions are prose in `payment/reviews/` and in the migration
  ledger. `CheckoutVolume` keeps its per-worktree suffix owner in `AddPostgresContainer`, so platform
  PR #11's regression — every consumer inlining `AddSqlServer` and losing the suffix — cannot recur.
- **`SqlServerContainerResourceTests` loses no coverage.** `PostgresContainerResourceTests` already pins
  the default, repeat and named-volume suffix contract and `AddDatabase` naming. The one assertion unique
  to the deleted file was that a SQL and a Postgres container share a checkout suffix, which is
  unstatable once one of the two container types is gone.
- **The remaining SQL Server surface is exactly the plan's allowlist.** `Microsoft.Data.SqlClient` stays as
  a package reference of `Concertable.DataAccess.Infrastructure`, used only by `DbExceptionExtensions.cs`
  and `SqlExceptionExtensions.cs` for the reviewed 2601/2627 duplicate classifier. It registers no runtime
  provider.

### Downstream obligation this candidate creates

Not a defect — the intended published break, recorded so it is owned rather than met as a red build:

1. `Aspire.Hosting.SqlServer` left `Concertable.AppHost.Shared`, and Auth, Customer, Payment and Search
   reach `SqlServerServerResource` **only** through that transitive dependency. Their `ResourceGraphTests`
   assertions that no such resource exists stop compiling at the next platform bump. Those assertions guard
   against a type nothing can produce any more and should be deleted, not re-referenced. B2B and System
   declare the package themselves and so compile either way, but carry the same now-pointless assertion
   and reference.
2. `UseSeedingSupport` is gone from the published `Concertable.Seed.Shared` API, with fourteen call sites
   across Auth (1), B2B (10), Customer (1) and Payment (1). Each drops the call; nothing replaces it.
